# S5 本地性能 Smoke 基线

此基线提供可重复的本地性能冒烟测试，不是跨机器 SLA，也不代表生产目标。测试仅构造合成设计文档，直接调用当前已构建的 Storage 与 renderer-canvas 模块；不启动真实模型、不读取项目用户文件，也不访问网络。

## 运行方式

先构建工作区模块，再运行脚本：

```powershell
pnpm build
node apps/desktop/scripts/performance-baseline.mjs
```

脚本在 `artifacts/s5-perf/run-<UTC 时间>-<PID>/` 创建独立输出，并写入 `results.json` 与 `summary.md`。每次运行使用新目录，不覆盖以前的结果；合成 Storage 工作区也只在本次 run 目录内。

基准涵盖三种规模（250、1,000、3,000 个子节点，另含一个根 Frame），每份文档有 1 页、0 个资产、5 条提交。每个规模创建 9 份独立文档，测量 journal 恢复的首次读取，以及同一合成工作区的重复恢复；另外测全量 SVG 截图和只裁切一个目标节点的 SVG 截图。每个文档对重复操作测 10 次。脚本先运行一份不计入数据的微型预热 fixture。

报告记录 OS、架构、CPU 型号/逻辑核数、总内存、Node/Electron 版本、输入文档与 journal 大小、操作 p50/p95/p99、进程峰值 RSS 和样本数。分位数使用线性插值；恢复“首次读取”指每个新 fixture 写完后的首个应用层恢复调用，数据写入可能已经使操作系统文件缓存变热，因此不能解释为冷盘延迟。重复样本是在相同 Node 进程、文档和 Storage 工作区中取得。

RSS 以 Node 进程的 `resourceUsage().maxRSS` 和 25 ms 采样结果取较大值；短于采样间隔的瞬时峰值可能漏掉。基准在 Node 进程内直接运行模块，不覆盖 Electron IPC、窗口绘制、GPU 光栅化、真实 PNG 编码/导出或外部 MCP 客户端往返。当前脚本选择持久化重放和真实 renderer-canvas SVG 渲染，是现有模块可在不启动 UI、且不依赖用户数据的情况下可靠复测的范围。

为避免读取仓库中已有 artifacts 的内容，脚本只在运行前后比较 `artifacts/` 顶层条目数/文件数/目录数（排除新增的 `s5-perf` 输出根），并比较 `artifacts/s5-perf/` 中本次 run 以外的同类计数；不会递归枚举、打开或散列既有 POC、用户数据或 Electron 缓存。所有基准读写仅限新 run 目录。计数核验可发现条目增删数量变化，但不是内容级完整性证明。

## 本次实测

2026-10-03 本机实测，原始结果位于 `artifacts/s5-perf/run-2026-10-03T06-30-30-961Z-1242560/`。

- 环境：Windows 11 Pro for Workstations x64；AMD Ryzen AI 9 H 365 w/ Radeon 880M，20 个逻辑核；Node v24.0.0；Electron 44.5.1。
- 内存：总计 31.1 GiB；测试开始时空闲 2.43 GiB；Node 基准进程峰值 RSS 约 503 MiB。开始时系统空闲内存偏低，且机器上有其他开发任务运行，尾延迟受后台负载影响的可能性较高。

这是一次受后台负载影响的开发机 Smoke 测量，不是稳定性 SLA。跨机器、Node 版本、磁盘缓存状态或系统负载比较前，应在目标环境多次重复；需单独增加 Electron 窗口、GPU、PNG 导出或 MCP 端到端测量时，应该在独立、合成且可丢弃的测试项目上另行基准。
